# C盘守护者

Windows 桌面文件分析工具：扫描大文件，解释常见软件文件的用途，并给出保守的清理建议。它也用于研究 Qwen3.5-0.8B 这类极小模型的微调和本地检索增强生成。

## 当前功能

- **文件扫描**：使用有限并发的目录队列遍历全部层级，Windows 上按文件句柄核验大小，再按阈值筛选；大小设为 0 可列出全部文件。隐藏、系统文件参与扫描，不跟随符号链接和目录连接点，未跟随的路径会列在报告中。权限、读取、路径解析等问题会使结果明确标记为部分完成；取消和失败分别显示。扫描覆盖所选目录树所在卷，逻辑大小不等于可释放空间，不包含命名数据流或时点快照。
- **结果完整性**：后端保留全部命中结果，按批传输并核对序号和数量，传输不完整时可从后端分页恢复。前端每页显示 100 条，分类、全选和复制仍涵盖当前分类的全部页；导出不再截断为 1000 条。硬链接按路径显示，合计可能重复计算同一文件实体。
- **本地解释**：Rust 内嵌 llama.cpp，使用 GGUF 模型；训练所需的 Python 不属于应用运行依赖。本地用途资料通过路径规则检索，覆盖 WebView2、OneNote 缓存、pip 缓存、PyTorch、Hugging Face 缓存、Node.js 依赖和两类临时目录。
- **云端解释**：支持 OpenRouter 和 OpenAI 兼容接口。配置 Tavily 后可为本地模式补充搜索资料；使用云端或搜索会向相应服务发送路径或查询信息。
- **安全分类**：红色为系统关键位置，黄色表示需要确认，绿色表示已识别的可清理类别。缓存名称、下载目录或 `.bak` 扩展名本身不足以判定安全；绿色也需要确认是否在用、是否需保留。
- **用户操作**：可打开文件所在位置，也可在界面中选择文件并确认移入回收站。项目实际存在删除功能，早期“不会执行任何删除操作”的说明不准确；AI 解释不会自动触发删除。

路径只能提供线索，不能证明文件内容、应用依赖或备份状态。未知路径应明确说明无法确定，解释和颜色都不能作为数据可恢复的保证。

## 实验和验证

2026-10-10 已完成三种量化模型的六组无资料/RAG对照，以及Qwen3.5-4B按NF4加载的检索感知LoRA训练与同基座RAG配对评测。三种GGUF的RAG严格资料忠实性为14/24、10/24、17/24；NF4配对在微调后从13/24提高到17/24，未知拒猜仍为6/7，自然度3.67→3.83，关键词23/24→19/24。38步训练验证NLL2.2960→1.9347，但这不是事实准确率；全部条件仍未达完整可靠性目标。评审为单助手可见配置复核，150条训练数据只有8种目标答案，也没有独立新知识泛化证明。见[完整报告](lora-training/experiments/2026-10-10/report.md)、[最终分析](lora-training/experiments/2026-10-10/analysis.md)与[研究计划和进度](lora-training/experiments/2026-10-10/progress.md)。本轮适配器尚未导出GGUF或用于应用集成，运行加载峰超过预设7GB显存目标。


2026-10-09 四组 0.8B 实验的 [结果与结论](lora-training/experiments/2026-10-09/RESULTS.md) 已公开保存：基础模型、纯 SFT、基础模型＋RAG、检索感知 SFT＋RAG 的固定关键词检查为 8/24、5/24、13/24、21/24。它们不是事实准确率；新模型仍有 pip 删除影响混淆和模板重复。

固定条件见 [实验协议](lora-training/experiments/2026-10-09/PROTOCOL.md)，脚本和训练流程见 [微调说明](lora-training/README.md)。原始回答以 JSON 保存，关键词检查和逐条事实审阅分别报告；验证 loss 不能替代实际回答质量。本机开发/资源目录已换为通过六条原生 smoke 测试的实验 GGUF，重启后生效；GitHub 不含模型权重，仍需按说明生成或放置文件。

历史上的 100.94 秒与 3.56 秒分别来自 30 层和 3 层扫描，不能用于证明完整扫描提速。当前完整性测试覆盖 100 层长路径、超过 1000 个命中、硬链接增长、系统/隐藏属性、连接点循环、拒绝访问、取消和传输核对。USN 枚举器保留为显式对照，校验记录版本、边界、完整文件标识及路径循环，并补查硬链接路径；应用默认不自动切换引擎。未启用旧 MFT 解析器、增量索引或快照。

## 开发

需要 Windows、Rust stable、Node.js，以及 [Tauri 2 开发环境](https://tauri.app/start/prerequisites/)。本地模型文件不存入 Git，需按微调说明生成或放置模型。

```powershell
cd frontend
npm install
npx tauri dev
```

设置中选择本地模型并加载，或配置云端 API Key、Base URL 和模型名。开发版优先读取 `lora-training/output/finetuned_model_gguf/qwen3.5-0.8b-q4_k_m.gguf`，然后尝试 `src-tauri/resources/`。修改或替换模型后需重启应用重新加载。

```powershell
# 前端检查
cd frontend
npm test
npm run lint
npm run build

# Rust 单元测试（从项目根目录执行）
cd ../src-tauri
cargo test --lib
```

实际模型测试默认忽略，可用 `local_model_chinese_and_explanation_smoke` 配合 `--ignored --nocapture` 运行。完整扫描基准用同一目录、大小阈值 0，预热后交错比较 1/2/4/8 个工作线程，各运行 3 次并逐条比较路径与大小。阶段耗时为各工作线程耗时之和，`elapsed_ms` 为实际总耗时。请选择稳定的测试目录，扫描期间变化会导致结果一致性断言失败：

```powershell
$env:SCAN_BENCH_ROOT = 'D:\scan-fixture'
cargo test --lib complete_scan_performance -- --ignored --nocapture
```

2026-10-10 本机 Windows debug 构建、热缓存夹具：128 个子目录各 128 个文件，根目录另有 2048 个文件，每个文件 128 字节。全部配置均找到 18,432 个文件，路径和大小逐条一致、零错误。1/2/4/8 线程的三次中位耗时分别为 961/633/424/313 毫秒；默认采用 4 线程。此结果仅衡量该夹具的后端完整扫描，不代表冷缓存、机械硬盘、整盘或界面总耗时。

`cargo run --bin export_scan -- <root> <min_size_mb>` 将全部命中以 JSON 数组写到标准输出，完整性摘要写到标准错误；部分完成或取消时退出码为 2，调用方仍可保留已经导出的部分结果。

## 构建

先将经过验证的 `qwen3.5-0.8b-q4_k_m.gguf` 放入 `src-tauri/resources/`，再执行：

```powershell
cd frontend
npx tauri build
```

安装包位于 `src-tauri/target/release/bundle/`。模型作为 Tauri resource 打包；模型加载、BF16 实验和安装包端到端验收是不同的检查，实验报告会说明实际完成了哪些。
