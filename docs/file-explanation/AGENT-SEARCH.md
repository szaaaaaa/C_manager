# DDGS 文件检索工具：调用与检索流程

2026-10-11，开发目录 D:\C_manager-file-explanation，分支 codex/file-explanation。

界面展示的是可核对的检索记录与依据摘要，不是模型内部思维链。摘要明确标注为模型整理；工具返回结果由程序记录，二者分开。

## 调用协议

不再让所有动作共用 target。模型提交带 action 的独立结构：

| 动作 | 参数 | 程序实际执行 |
| --- | --- | --- |
| search | query、site | DDGS 中文查询；site 非空时追加 site: 域名并按返回 URL 主机再次过滤 |
| open_page | source_id、focus | 读取已发现来源的正文，关注指定主题 |
| review_source | source_id、relation、note | 阅读后核对来源与目标软件的关联：相关、不匹配、未确认 |
| find_in_page | source_id、terms | 在已读来源中寻找具体关键词及邻近段落 |
| reject_sources | source_ids、reason | 排除摘要中已经明显不匹配的候选 |
| finish | 无 | 结束检索，保留未解决问题 |

source_id 与关键词分离。本地模型每轮使用动态 GBNF，只能选择当前可用动作、实际来源编号和候选域名；云端输出执行同样的程序校验。查询要求含中文，可保留英文软件、组件名及数字。

## 调度顺序

1. 从初始线索与本机证据出发，核对归属、用途、删除影响及处理方式。
2. 搜索得到新候选后，先选择阅读，或明确排除不匹配候选。
3. 读取后先审核来源归属。不匹配来源退出可用上下文和最终证据包，编号不复用。
4. 只有被模型判断与目标软件相关的来源，其域名才进入后续站点候选。首次补搜优先使用尚未检索过的相关站点，之后可扩大范围。软件官方身份仍需资料支持，程序不会仅凭域名命中就标为官方。
5. 用带引用的短摘要记录各项已经检查的内容，针对剩余缺口补搜。摘要覆盖度只是调度记录，不是内容正确性的证明。
6. 最多 8 次搜索/正文读取/页内查找；来源审核不算联网操作。预算用完仍允许最后一次总结。两次参数错误或连续两次没有新增资料时停止，避免耗尽轮次重复原查询。

没有预设“某文件一定是什么”的答案，也没有按扩展名限制搜索。

## 展示与证据边界

每步展示阶段目标、实际查询或来源编号、限定站点/关键词、执行结果、模型依据摘要及引用、待确认项、本步来源链接。不把“想查官网”的文字当作已经查询官网，也不把摘要当正文。

最终释义仍读取原始证据，不把检索摘要充当新的事实。最终最多保留 4 条来源，优先已读和近期引用的资料；被排除来源不进入最终答案。未完成核实或仍有缺口时不输出删除许可。

隐私与网络限制沿用原实现：不向搜索引擎发送完整路径、用户名及未授权私有目录；网页抓取检查公网 IP 并固定解析地址，不访问内网、不跟随重定向、不运行脚本，单页上限 1 MiB。搜索和读取工具各 30 秒超时，模型规划另计。中文 URL 的路径和查询用 UTF-8 百分号编码，保留已有转义。

规划输入限制本机证据和正文片段长度。网页截取与小模型上下文仍可能遗漏信息；没有新增全文浏览器能力。
