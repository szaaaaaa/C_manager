# 五类文件处理判别

本版新增 decision 与 condition，贯通 Rust反序列化、本地GGUF语法约束、云端提示和前端展示，不增加分类头或概率显示。

- direct_delete：可直接删除。用途、影响、处理三个字段均须有supported状态及有效引用。
- managed_cleanup：通过系统或软件清理。处理说明给出有依据的管理入口，不将关闭功能等同于清缓存。
- conditional_delete：满足条件后可删除。condition必填，并在首屏显示，不藏在来源折叠区。
- keep：建议保留。依据已知功能或数据影响说明原因。
- unknown：暂无法判断。condition必填，说明缺什么信息。没有引用的用途/影响不展示模型推测，使用未知说明。

“能不能删”先显示固定结论、条件和简短理由/方式；“删了会怎样”说明对应操作的损失、功能变化或后续下载；“有什么用”说明平时作用。所有非unknown判别必须具有用途、影响与处理依据。引用存在并不等于资料在语义上确实支持结论，此校验不能替代事实核实。

验证：前端27通过、1个性能基准跳过；后端36通过、11个显式忽略。真实Qwen3.5-4B以固定官方资料和合成路径实测：传递优化缓存输出managed_cleanup；游戏目录同名content.bin输出unknown。本次不操作这些真实文件。发现unknown时模型仍编造无引用后果，已增加收回逻辑并通过6项释义校验回归。未逐一验证其他模型、五类的真实准确率或实际删除行为。
