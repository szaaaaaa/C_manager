# Qwen3.5-0.8B 文件解释对照实验

开始日期：2026-10-09 UTC / 2026-10-10 北京时间。目标是检查极小模型能否在本地给出可靠、自然的文件解释，不预设微调一定胜出。

## 固定条件

- 测试集：[eval_cases.json](../../data/eval_cases.json)，24 个手写测试路径；训练路径使用 Train/Example，测试使用 Eval、中文用户及不同版本号、盘符、文件名。测试的未知目录也包含会误导模型的品牌名和 cache 前缀。
- 测试集 SHA256：`a516f0f456d18ba589034e23f3a3e47cefb5762f7436387bf22d502d4372603b`。这份测试集在 RAG-SFT 训练前冻结；如修正测试错误，应另记新版本，不能覆盖原结果。
- 16 个常见路径、6 个未知/近似路径、1 个混入无关资料的测试、1 个缺失正确资料的测试。知识库只覆盖八类路径，不代表整盘软件覆盖率。
- 同一 GPU、BF16 推理、相同系统指令和安全分类、greedy 解码、seed=42、最多 256 个输出 token，显式 `use_cache=True`。只有 RAG 组附加用途资料；测试推理不走应用的规则回复或网络搜索。早期试运行发现纯微调的 HF 配置保存了训练时的 `use_cache=False`，该部分耗时结果作废；在统一缓存设置后重跑四组。
- 固定本地路径检索，无向量库、联网资料搜索或文件内容读取。它是检索增强生成的一种具体实现，但不测试通用语义检索能力。
- 基础模型仓库版本：`unsloth/Qwen3.5-0.8B` 的 `23c69c53358a07516b5827588b3fdb12ae78fd65`。下载的 BF16 权重文件 SHA256：`04b1c301231dd422b8860db31311ab2721511346a32cb1e079c4c4e5f1fe4696`。基础与纯微调模型的 `tokenizer.json` 字节完全相同，SHA256 为 `87a7830d63fcf43bf241c3c5242e96e62dd3fdc29224ca26fed8ea333db72de4`。
- RAG 训练记录同时保留当时 CRLF 输入的原始哈希和 `data_sha256_lf`。提交前只规范了行尾，逐条验证 168 个 JSON 对象未变；仓库属性及生成脚本固定 LF，跨平台复现可使用 LF 哈希核对。

## 四组

| 组 | 权重 | 推理时用途资料 |
|---|---|---|
| base-plain | 下载的原始 `unsloth/Qwen3.5-0.8B` | 无 |
| sft-plain | 本次修复流程产生的纯 SFT 权重 | 无 |
| base-rag | 同一原始基础权重 | 本地知识库 |
| sft-rag | 从同一原始基础权重重新训练的 RAG-SFT | 同一知识库 |

纯 SFT 是已完成的基线：604 个有效样本，549 训练 / 55 验证，3 epoch、207 step、lr=2e-4；随后针对错误命令等内容用 133 个样本继续训练 1 epoch、16 step、lr=5e-5。它与 RAG-SFT 的数据和预算不同，因此结果只能比较这些具体配方，不能把差异全部归因于 RAG 或 LoRA。

RAG-SFT 使用 [generate_rag_data.py](../../scripts/generate_rag_data.py) 生成的 168 个样本，包含相关资料、混合无关资料、缺失资料和未知路径。基础知识与自然回答分开记录，推理上下文不包含 `answer` 字段。训练参数由 [train_rag.py](../../scripts/train_rag.py) 固定：BF16 LoRA，r=16、alpha=16、dropout=0.05，2 epoch、lr=1e-4、batch=2、gradient accumulation=4；每 10 step 验证并保存，按验证损失选择 checkpoint，只计算回答部分的损失。按完整知识类别划分验证集，避免同类别的路径改写同时进入训练和验证。

## 评价和边界

`evaluate.py` 保存逐条原始回答、输入/输出 token、生成耗时、软件版本和数据哈希。`cue_pass` 只是预先指定的关键词/禁止短语检查，不是事实准确率；正确的同义表达可能失败，包含关键词的错误回答也可能通过。

结果还需要逐条核对：用途有没有捏造，删除影响是否说清楚，是否遗漏可能丢失未同步笔记的风险，未知路径有没有明确承认不确定，以及是否过度笼统或重复模板。本次由 Codex 作逐条事实审阅，应单独记录理由；未进行双盲人评或专家复核。自然度只作定性描述，不用无依据的主观百分比。

GPU 的生成耗时不包括模型加载，第一条可能含编译/预热；报告给出全部样本的中位数和范围，同时公开逐条时间。它不能直接当作桌面 CPU llama.cpp 的延迟。BF16 实验结束后还要单独验证 Q4_K_M 与应用链路。

这是受控小样本试验，知识库与训练事实存在重叠，干扰资料的标记也比较明确。需要更大、独立软件类别的盲测，才能支持普遍准确率或 RAG 消除幻觉的结论。DPO、GRPO、全参数微调和更大的模型不属于本轮对照。
